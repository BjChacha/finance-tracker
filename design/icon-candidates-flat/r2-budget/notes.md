# 2 · 预算环 Budget Ring

## 概念与含义

- **一句话**：一圈 = 一个月的预算。琥珀弧 = **已经花掉的预算（72%）**，浅石灰色轨道 = **还剩的预算**；弧的两端是圆头，像进度条的两端。环心留白，不放货币符号或数字。
- **环不是装饰**：轨道是「本月可花的总量」，琥珀弧是「已用掉的部分」，两者共用一个圆——弧长即进度，缺口即剩余。它把记账 App 最常用的「预算/消费建议」直接变成一个形状。
- **与产品**：对应「花哪了」的预算与消费建议能力；也暗示「消费有度」——环还没闭合，一切都还来得及。
- **为什么不是箭头**：方案最初是「流动环（环+三角箭头）」，但箭头与 96px 粗环的接缝在 48px 下会被读成「断掉的 C / 缺角的环」，试了 9 组箭头几何仍不够干净。预算环同样承载记账语义，而且**几何天然就是进度**，小尺寸不需要解释。

## 几何（1024 画布，viewBox 0 0 1024 1024）

| 项 | 值 |
| --- | --- |
| 画布 | 1024 × 1024，纯白 `#FFFFFF` 全出血 |
| 环中心线半径 | **260** |
| 描边宽 | **96**（外半径 308，内半径 212） |
| 轨道 | 完整圆，1024 画布内径 212–308 |
| 进度弧 | 从 12 点开始顺时针 **259.2°（= 72%）**，止于左下（约 8:36） |
| 端点 | **圆头 `round`**（两端半径 48） |
| 中心 | 留白半径 212，无任何符号 |

进度弧路径：`M 512 252 A 260 260 0 1 1 256.6 560.7`。

## 色值（3 色，全实色）

| 角色 | 色值 | 说明 |
| --- | --- | --- |
| 背景 | `#FFFFFF` | 纯白全出血 |

## 设计取舍

1. **72% 而不是 50/90%**：72% 留出明显的「未用完」段（约 100°），大尺寸下进度与剩余都清楚；48px 下也能读出「环没走完」，比 50% 更像进度、比 90% 更有余量。
2. **圆头端点**：进度类环形图标用圆头更柔和，也和 r1 配置环的平头形成有意区分（r1 是份额、要精确；r2 是进度、要流动感）。
3. **浅灰轨道 `#D6D3D1`**：比 `#E7E5E4` 更可辨、又不会抢琥珀；在白底上仍是「安静的背景层」，符合「最基础、最极简」。
4. **中心留白**：不放「72%」「¥」或圆点——数字与金额属于界面，图标只表达「预算用了一大半」这件事。
5. **单色层只保留琥珀弧**：Android 13 主题图标重新着色后，72% 的开环仍是「预算进度」，而不是一个无信息的整圆。

## 自检

- 四个 SVG 均为独立合法 XML：`width=1024 height=1024 viewBox="0 0 1024 1024" xmlns`；无 `<text>`/`<image>`/外链/字体/脚本/滤镜/渐变/透明度。
- `icon.svg`：白底全出血，四角不透明；1024 下环厚 96、轨道与弧对比清晰。
- `adaptive-foreground.svg`：透明底，内容最大半径 308 ≤ 330（660 安全圆），四角透明。
- `adaptive-background.svg`：纯白全出血。
- `adaptive-monochrome.svg`：透明底 + 纯白 72% 弧，四角透明。
- 48px：琥珀弧 / 浅灰轨道 / 环心留白三者同时可读，不会被误读为「断环」。

## 迭代记录

1. 原任务概念为「流动环（缺口 + 三角箭头）」，designer-r2 迭代多版（箭头融入环、同色/黑色箭头、不同缺口角度与旋转），1024 尚可但 48px 均读成「断环 + 尖角」，不够干净。
2. Lead 决策改为「预算环 / 进度环」：保留环的语言与琥珀主色，用「已用 / 剩余」两段表达预算进度；几何一次成型，48px 可读。
3. 最终几何与配色经 1024 / 128 / 48 三档渲染确认。
