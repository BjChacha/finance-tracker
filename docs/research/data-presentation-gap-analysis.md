# 图表复用现状 × 数据呈现缺口分析

> 对照基准:Sure 最新快照的 11 类图表 + 布局组件(见 `sure-chart-component-inventory.md`)。
> 本文回答两个问题:**① 这些图型我们哪些用上了、用来呈现什么数据;② 哪些数据我们根本没呈现。**
> 所有结论均经代码核查(统计层 `src/features/stats/*`、仪表盘层 `src/features/dashboard/*`、数据模型 `src/db/schema.ts`)。

---

## 已落地(2026-11-24,P0 + 两张新图)

> 下文速览与清单记录的是**改造前**的基线,保留作为对照;本节列出已经补上的部分。

| 原缺口 | 落地位置 | 说明 |
|---|---|---|
| 死管线 `categoryRank` | 统计页「分类明细 · 排行」 | 按末级分类排行(与一级归并口径不同,卡片内有提示),可点下钻流水 |
| 死管线 `accountDistribution` | 资产页「账户构成」 | 环形图,仅含余额为正的账户(卡片内有提示) |
| 死管线 `netWorthTrend` | 资产页「近 12 个月净值」 | 固定 12 个月,与所选周期解耦 |
| `weekdayPattern` 只喂 AI | 统计页「星期分布」 | 七根柱为**日均**金额(分母含无支出日),并给出工作日/周末日均与周末占比 |
| 无桑基图 | 统计页「资金流向」 | 自绘 `SankeyChart`:账户 → 分类,缎带宽度表示金额 |
| 无多序列折线图 | 统计页「分类明细 · 趋势」 | 自绘 `MultiSeriesLineChart`(gifted-charts 只支持 2 序列);窗口不足 6 个月时自动向前补足 |

「趋势 / 合计 / 排行」三个视角最终收敛为**一张** `CategoryDetailCard`:三者是同一批数据的
时间维、占比维、排序维,并排铺开会让统计页过长且信息重复;合并后共用页面的「支出/收入」
选择,并且**只查当前视角**(切到排行才发排行查询)。

仍未落地:`projectId` / `tags` 聚合、`categorySource` 统计视图、treemap 的「偏离常态」着色、`monthlyCompare` 与 `transactionDateRange` 两条死管线。

## 一、图型对照:我们用上了哪些

### 1.1 已用上的(6 类)

| Sure 图型 | 我们的实现 | 行数 | 用在哪 | 呈现什么数据 |
|---|---|---|---|---|
| 时间序列折线/面积 | `TrendLineChart` | 273 | **5 处**:统计页收支走势、资产卡(净值/资产/负债三切换)、消费节奏累计对比、个人资产「持有成本趋势」+「变现趋势」 | 按周期聚合的收支/净值/成本序列 |
| 净值图 | `TrendLineChart`(metric=netWorth) + `sparklineGeometry` | 28 | 资产卡、看板资产摘要 | 净值折线 + 迷你趋势线 |
| 分组柱状 | `CompareBarChart` | 111 | 统计页「月度收支」 | 近 N 月 收入 vs 支出 |
| 累计双线对比 | `TrendLineChart`(双序列) | — | 看板「消费节奏」 | 本期 vs 上期累计支出 |
| 甜甜圈 | `DonutChart` | 75 | 统计页分类构成(支出/收入)、个人资产持有成本构成 | 一级分类占比 / 资产类别占比 |
| 树状图 | `CategoryTreemap` | 175 | 分类列表(看板 + 统计页 + 分类面板三处复用) | 分类占比(面积=占比) |
| 服务端/静态 sparkline | `sparklineGeometry` | 28 | 看板资产摘要 | 净值迷你线(零交互) |

配套几何模块:`donut-layout`(170)、`smooth-line`(133)、`donut-data`(76)、`treemap-layout`(46)、`line-axis`(39)、`chart-layout`(10)。
另有 `CalendarHeat`(244)是**我们独有的**——Sure 没有日历热力图。

### 1.2 Sure 有、我们没有的(5 类)

| 图型 | Sure 用在哪 | 我们的缺口后果 |
|---|---|---|
| **桑基图** | 现金流(收入→分类→账户) | **资金流向完全无法呈现**;转账在两侧账户间的流动也没有视图 |
| **多序列折线** | 报告页「分类趋势」(可勾选任意多个分类) | **单个分类的逐月走势无法对比**——想做「餐饮 vs 交通这半年怎么变」做不到 |
| 目标投影 | 目标达成预测 | 无目标(g

oals)模块 |
| 贷款还款多序列 | 本息/计划/实际/提前 | 无贷款模块 |
| 进度环 | 目标环、贷款进度 | 预算进度目前是**横条**而非环(视觉差异,非能力缺口) |

### 1.3 同类图型、我们的用法差异

- **树状图**:Sure 是「面积=金额、**颜色=与常态的偏离 6 档**」,我们只按分类色着色 → **同一张图少了一个维度**(见下节 C-2)
- **分组柱**:Sure 的支出柱故意用中性灰,我们已对齐
- **折线**:Sure 支持 brush 框选缩放,我们是固定周期切换

## 二、数据呈现缺口(核心)

### A. 已存字段、从未进入任何图表或聚合(9 项)

| 数据 | 存在形式 | 现状 | 后果 |
|---|---|---|---|
| **项目** `transactions.projectId` + `projects` 表 | 完整两级管理页 | 统计层/dashboard 层 **0 处**聚合 | 项目只是「标签式归属」,**无法回答「这次旅行一共花了多少」**——而这正是项目功能存在的意义 |
| **标签** `transactions.tags` | JSON 数组,写入/备份/CSV 导出/明细行 chips 展示都完整 | 唯一被聚合的是「智能」标签(用于智能识别统计卡) | **标签不能筛、不能算**:无法「筛选含某标签的交易」,也无法「按标签聚合金额」 |
| **分类来源** `transactions.categorySource` | 5 种来源(manual/rule/suggestion/nl/import)只在保存时写入 | **只写不读——0 处引用** | 我们为「规则/建议/AI 谁更准」专门落了库,却没有任何统计视图;规则页显示的采纳率走的是 settings 里的计数器,与这个字段无关 |
| **转账手续费** `transactions.fee` | 独立字段 | 被折进支出总额(仅 labels 有文案) | 无法看「手续费累计花了多少」「哪个账户转账最贵」 |
| **多币种** `currency` / `exchangeRate` / `amountBaseCents` / `toAmount` | 完整多币种支持 | 统计层 **0 处**按币种聚合 | **外币消费无法单独分析**;所有图表只呈现折算后的人民币口径 |
| **录入时间** `createdAt` / `updatedAt` | 有 | 0 处呈现 | 无「记账习惯」分析(如补记比例、记账频率) |
| 导入指纹 `fingerprint` | 有 | 0 处呈现 | 仅内部去重用(合理) |
| 周期规则 `lastRunDate` | 有 | 展示层 0 处 | 无法看「上次自动入账是什么时候」 |
| 规则 `lastMatchedAt` | 有 | 展示层 0 处(仅 `matchCount` 显示) | 无法判断规则是否还有效(上次命中多久前) |

### B. 5 条「死管线」:数据算好了,没接界面

这些是已实现的聚合函数,**定义在 repository 里、有对应 hook、但没有任何界面引用**:

| 函数 | 本可呈现什么 | 状态 |
|---|---|---|
| `accountDistribution()` | **账户构成环形图**(按余额排序的账户切片) | 有 hook `useAccountDistribution`,零引用 |
| `netWorthTrend(n)` | **近 N 月净值趋势折线** | 有 hook `useNetWorthTrend`,零引用 |
| `categoryRank(range,type,limit)` | **分类排行 HBar**(含二级分类独立) | 有 hook `useCategoryRank`,零引用 |
| `monthlyCompare(n)` | 近 N 月收支对比 | 有 hook `useMonthlyCompare`,零引用(统计页用 `useTrend('month')` 实现了类似效果,属重复) |
| `transactionDateRange()` | 全部交易日期范围 | 有 hook,零引用(实际用 `useAssetHistoryStart` 替代了) |

> 注:`accountDistribution` / `netWorthTrend` / `categoryRank` 是**真实能力缺口**;**monthlyCompare / transactionDateRange** 是被更好实现取代的死代码,可删。

### C. 算了、只在 AI 文字里出现过、没画出来(4 项)

| 数据 | 现状 | 缺口 |
|---|---|---|
| **工作日/周末支出对比** | `reports/snapshot.ts` 计算 `weekdayExpenseCents` / `weekendExpenseCents` 并喂给模型;报告以**文字**呈现 | **没有图**。「我周末是不是花太多」是最典型的一眼需求,数据已经在算 |
| **储蓄率** | 洞察里一条文字(`savings_rate_change`) | 无储蓄率**趋势图**(逐月/逐季) |
| **订阅月度折算** | 洞察里一条文字 | 无「订阅月度总额」的独立呈现(且 Sure 的订阅审计是可下钻清单) |
| **分类环比** | `CategoryList` 里有文字 delta(`对比 -¥40.86`) | 有数字无图(Sure 用 treemap 颜色表达同一件事) |

### D. 模型层就缺失的数据(Sure 有、我们没有)

这些不是「没画出来」,而是**根本没有数据**,列出以区分优先级:

| Sure 有 | 我们的情况 | 影响 |
|---|---|---|
| `balances` 余额按日快照表 | 净值靠交易流**回算** | 无法呈现「任意时点余额」,账户余额历史依赖回算口径 |
| `merchants` 商户体系 | 只有自由文本 `note` | 无商户维度分析(如「在星巴克一共花了多少」) |
| `holdings` + `securities` + `security_prices` | 只有 `personalAssets` **成本台账**(明确不做估值) | 无市值/收益曲线 |
| `loans` / `goals` / `account_statements` | 无 | 无还款计划图、目标投影、对账 |
| 投资 `trades` | 无 | 无投资流向图 |

## 三、差距归因:三种不同类型的「没呈现」

把上面的缺口按**性质**归类,能看清该补什么:

1. **数据在手、只差一张图**(最低成本、最高感知)
   - 账户构成环(`accountDistribution` 现成)
   - 净值趋势折线(`netWorthTrend` 现成)
   - 分类排行(`categoryRank` 现成)
   - 工作日/周末对比(`weekdayPattern` 现成)
   - 分类趋势多序列(需新图型 + 新聚合)

2. **数据在手、但缺的是「维度」而非图形**(中等成本)
   - 项目聚合(projectId 已索引 `idx_tx_project`,聚合很便宜)
   - 标签筛选 + 标签聚合
   - 多币种视图(currency 已索引?需查)
   - 手续费独立呈现

3. **数据根本没采集**(高成本,需先决策)
   - 余额快照表 / 商户 / 投资市值 / 贷款 / 目标

**第 4 种特殊情况**:`categorySource` 属于「采了但白采」——它已经写进每一笔交易,却连一个「规则 vs 建议 vs AI 谁更准」的视图都没有。我们上一轮专门加了字段和采纳率计数,字段本身却闲置。

## 四、按性价比排序的建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | 接上 3 条死管线:账户构成环 + 净值趋势折线 + 分类排行 | 聚合函数和 hook 都写好了,**只差渲染**,一个下午的量 |
| **P0** | 工作日/周末支出对比图 | 数据已在 snapshot 里算,是最容易产生「原来如此」的一眼洞察 |
| **P1** | 项目维度聚合(项目花费总览 + 排行) | `projectId` 已建索引;项目功能目前只有归属没有回报,补上才算闭环 |
| **P1** | 标签筛选 + 标签聚合 | tags 已是实体属性,补一个筛选入口和「按标签看金额」 |
| **P1** | 分类趋势多序列折线 | 唯一需要**新图型**的一项,但把 `TrendLineChart` 扩展成多序列即可,不必照抄 Sure 的 361 行 |
| **P2** | 树状图加「偏离常态」颜色编码 | 不改数据、只改填充规则,info 密度翻倍 |
| **P2** | `categorySource` 统计视图 | 让「规则/建议/AI 谁更准」可见,指导后续是否调阈值 |
| **P2** | 多币种 / 手续费独立视图 | 数据完整,但用户规模可能不大 |
| **P3** | 余额快照 / 商户 / 投资市值 | 需先做产品决策 |
| — | 清理 `monthlyCompare` / `transactionDateRange` 死代码 | 已被更好实现取代 |

## 附:核查方法

- 图表清单:`src/features/stats/charts/` 全量文件 + 行数
- 使用点:全仓 `tsx/ts` 正则匹配组件名(排除测试与定义文件)
- 数据维度:对 `stats/`、`dashboard/` 目录匹配字段名,计数为 0 即判定「未参与聚合/呈现」
- 死管线:对每个 repository 函数在全仓 UI 文件搜引用,排除测试/hooks/repository 自身
- 展示层口径:排除 `repository.ts` / `schema.ts` / `service.ts` / `upgraders.ts` / `migrations` / `backup` 后的 UI 文件集合
