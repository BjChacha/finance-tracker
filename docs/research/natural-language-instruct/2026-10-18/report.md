# 本地指令模型与 harness 验证

日期：2026-10-18。结论：**当前候选未通过质量、延迟和内存门槛，不进入产品流程接入。** 本轮完成候选选择、无微调harness、结构/语义评测和红米真机测量，没有实现应用入口和交易预览页面。

约束解码在这批测试中达到了结构合规，但没有解决记账含义错误。系统可以拒绝违反业务约束的结果，无法把“结构合法”提升为“理解正确”。这不意味着所有无微调本地模型路线都不可行。

## 候选与实现

选择 [LiquidAI/LFM2.5-350M](https://huggingface.co/LiquidAI/LFM2.5-350M)：官方列出中文支持，并推荐数据提取、结构化输出和工具调用；这是选型依据，不是本应用准确率保证。使用 [官方GGUF](https://huggingface.co/LiquidAI/LFM2.5-350M-GGUF) revision `657e078c94084481950a2d555a941481f715536b`，运行时固定 [llama.cpp b11669](https://github.com/ggml-org/llama.cpp/releases/tag/b11669)，CPU四线程、4096上下文、单请求槽。

没有针对本项目微调，也未使用QAD权重。从官方F16量化，以旧开发集每隔5条抽取的20条提示生成校准文本；imatrix计算20个512-token块。**这是有限长度的量化校准，不保证覆盖校准文本全部尾部样例**，未优化到最佳量化配方。

比较协议采用 `prompt-selected.txt`：英文说明和当前有效分类/账户上下文。代码列出金额原文候选并转换为整数分，由模型选择。GBNF限定字段、枚举、候选ID和空白长度；之后独立校验分类类型、账户是否被提及、同名账户、转账源/目标等。[llama.cpp语法文档](https://github.com/ggml-org/llama.cpp/blob/b11669/grammars/README.md)说明了这种约束机制。

模型只输出提案，脚本不调用交易mutation或数据库。缺少字段、未知日期及弃权进入待补充状态；截断或结构错误进入失败状态。用户确认边界仍须在后续产品接入阶段实现。

## 结构与语义结果

使用原100条开发集调试；冻结提示、代码和上下文后，运行新测试集。新集为160条单笔、40条应澄清样例；32个单笔模板、8个边界模板各扩展5种金额写法。旧测试集没有作为本轮新测试结果复用。

**所有语料仍待人工核验。** 模板扩展样例存在相关性，下列数字不能解释为真实用户分布上的正式产品准确率。开发/测试模板未混用，但业务类别存在重叠。

| 新测试集指标 | 结果 | 解释 |
| --- | ---: | --- |
| 结构合规 | 200/200，100% | 本次样本观测，不是任意输入和运行故障下的保证 |
| 业务一致性 | 26/200，13% | 无当前规则检出的冲突，仍可能缺字段或理解错误 |
| 字段齐全的预览提案 | 9/200，4.5% | 不代表这些交易记对了 |
| 需要补充、纠正或重新输入 | 191/200，95.5% | 包括业务拒绝和缺少字段 |
| 应澄清样例被模型正确弃权 | 35/40，87.5% | 其余5条误判为单笔 |
| 明确单笔被模型保留为单笔 | 39/160，24.375% | 其余过度弃权 |

“可用字段命中”要求结构通过、模型未弃权、整体业务校验未拒绝；缺少账户可保留已识别字段。失败和弃权计入未命中，不从分母删除。原始字段命中仅用于诊断，不能替代门槛。

| 单笔指标 | 原始字段命中 | 可用字段命中 | 门槛 |
| --- | ---: | ---: | ---: |
| 金额整数分完全匹配 | 150/160，93.75% | 9/160，5.625% | ≥99% |
| 交易类型 | 49/160，30.625% | 9/160，5.625% | ≥95% |
| 一级分类 | 5/160，3.125% | 0/160，0% | ≥90% |

测试分类均为一级分类；自定义分类由每条输入的上下文动态加入，没有作为固定模型类别。原始账户角色匹配141/160，转入账户24/160，日期枚举73/160。模型经常将付款账户同时填入转入账户，或输出类型/分类冲突；机械校验能拒绝这些错误，不能纠正含义。

同模型、同提示、20条开发集控制样例：关闭约束时结构通过 **0/20**；约束版本对应记录通过 **20/20**。未约束输出常只有原文的 `text` 字段。未添加格式修复重试，不能外推所有提示方案的上限。

开发阶段还比较了Q4和更严格的跨字段语法，均未达标：

| 开发版本，100条 | 结构通过 | 业务一致性 | 单笔可用金额/类型/分类，分母80 |
| --- | ---: | ---: | --- |
| Q4 + 冻结候选枚举协议 | 100 | 68 | 41 / 42 / 17 |
| 混合量化 + 同协议 | 100 | 24 | 4 / 0 / 0 |
| Q4 + 简短提示、跨类型分类约束 | 100 | 100 | 5 / 50 / 4 |
| 混合量化 + 简短提示、跨类型分类约束 | 100 | 77 | 44 / 3 / 1 |

更严格的语法提高了业务一致性，但没有稳定提高语义准确率。这里保留策略对照的失败结果，不把最后一次尝试称为最佳提示，也不将结果归因于单一模型因素。

## 资源与真机

模型大小使用十进制MB，预算为150,000,000字节。

| 权重 | 字节 | 150 MB预算 |
| --- | ---: | --- |
| F16来源 | 711,485,152 | 不通过 |
| 官方Q4_K_M对照 | 229,312,224 | 不通过 |
| 默认Q2_K | 160,597,728 | 不通过 |
| pure Q2_K | 118,941,408 | 通过，但开发集质量差 |
| 校准Q2_K_S | 154,183,680 | 不通过 |
| 校准Q2_K_S，词嵌入Q4_K | 136,882,176 | 通过，本轮预算候选 |

预算候选加许可证、冻结提示和清单合计 **136,894,835字节（136.895 MB）**。GGUF包含分词资源。见 [资源清单](model-bundle.json) 和 [候选SHA256](audit.json)。这不是APK增量：运行时库及应用集成开销没有计入模型资源。模型遵循随权重保存的LFM Open License v1.0，未标注为Apache/MIT。

设备实读为红米M098FE、SoC SM8850、Android 16、arm64-v8a，serial `57721e63`。原生独立llama.cpp进程从手机本地文件加载模型，仅绑定loopback，不调用在线推理服务。

| 性能指标 | 结果 | 原目标 |
| --- | ---: | ---: |
| 进程冷启动到解析完成p95，20次 | **7,536.75 ms** | ≤3,000 ms |
| 常驻模型热解析p95，60次 | **5,680.27 ms** | ≤1,000 ms |
| 隔离推理进程采样峰值PSS | **323,683,328字节，323.68 MB** | 参考额外PSS ≤300 MB |
| 手机输出结构通过 | 冷20/20，热60/60 | 不等于手机语义正确 |

PSS采样1,795条，无采集错误；间隔200ms加ADB读取时间，可能漏过更短峰值。该值是独立进程总PSS；**React Native应用增量PSS尚未测量**。当前原生服务原型超过参考预算，但不能视作未来嵌入式运行时的不可优化下限。

冷启动重建进程、模型和KV，不清OS文件页缓存，不是手机重启后的磁盘冷加载。热请求保留共享前缀缓存、轮换输入。冷样例为开发集前20条，热样例为第2至61条，不代表全部输入分布。测量包含USB转发、请求和主机校验。电池温度35.7°C升至38.4°C，设备连接USB；未关闭其他应用或建立严格热环境。

Perfetto有效区间约19.97秒。推理进程PID8670累计运行75.33 CPU秒，约占3.77个核心；可运行等待合计约0.306秒，无trace解析错误。运行时自身计时中，冷请求提示处理/生成中位数约5,040/1,227ms，热请求约3,655/1,396ms。当前耗时主要发生在模型计算；尚未系统优化其他线程数、后端或任务拆分。

首轮Perfetto输出目录权限错误，未形成完整汇总，已排除。修正为系统trace目录后重新进行了上述完整测量。见 [真机汇总](android-q2s-selected.json)、[trace分析](trace-analysis.json)。原始trace、PSS和80条请求记录保留在仓库 `artifacts/natural-language-instruct/reports/android-q2s-selected/`。临时推理进程和端口转发已关闭。

## 失败样例与交付边界

- “小区临时停车，用微信付了37.25元”：金额候选正确，却输出转账、存钱、微信转微信及错误日期，校验拒绝。
- “储蓄卡的存款利息到账37.25元”：输出转账类型和工资分类，类型/分类冲突。
- “拿现金37.25元存入我的银行卡，办理成功”：源和目标都填成银行卡，且要求澄清。
- “买制作陶泥手工的材料，支付宝付37.25元，记在手工材料”：上下文提供了自定义分类，仍错分为红包。

保留 [失败列表](failures.tsv)、[200条原始预测](q2s-selected-heldout-predictions.jsonl)、[未约束对照](q2s-unconstrained-control-predictions.jsonl) 和 [评测汇总](q2s-selected-heldout.json)。

复现和验证命令见 [工具说明](../../../../scripts/natural-language/instruct/README.md)。合约检查覆盖整数金额、原文位置、非法结构/ID、业务冲突、同名账户、自定义分类、日期、截断、输入边界和弃权分母；代码/提示/数据冻结哈希复核一致。没有应用代码改动，未把上一轮类型检查和QuickActions测试当作本轮集成验证。

尚未完成：人工标注验收、React Native嵌入、客户端字符位置/分词对齐、首装断网、入口交接、预填保护、取消和进程重建、幂等保存及界面回归。没有交易表迁移或写入。

建议保留“模型提案→结构校验→业务校验→人工确认”边界，重新评估中文模型和资源预算。继续不微调也可以试验，但不能承诺靠skill、系统提示或tools将语义错误变成100%正确交易。本轮证据支持拒绝当前组合，不支持上线，也不支持推断所有本地无微调方案必然失败。
