# 一句话记账：首轮离线模型验证

日期：2026-10-18。结论：**本轮未经记账领域微调的 UIE-micro + BGE-small-zh-v1.5 候选没有达到质量门槛，暂不进入产品接入阶段。**

已交付可复现的下载校验、权重转换、ONNX 量化、整数金额转换、候选解析、语料检查、评测与失败报告。没有变更应用入口、交易表单、数据库或应用依赖。全局悬浮按钮、文本 Activity 和保存链路仍是待实施项。

## 质量结果

本轮有 100 条开发样例与 200 条测试样例；测试集含 160 条明确单笔和 40 条需澄清输入。**语料由助手编写，尚未完成独立人工核验**，因此下表是工程可行性实验结果，不是正式验收成绩。弃权计入未命中。

| 指标 | ONNX FP32 | ONNX INT8 | 目标 |
|---|---:|---:|---:|
| 金额完全匹配 | 143/160（89.38%） | 143/160（89.38%） | ≥99% |
| 收支类型 | 0/160，全部弃权 | 0/160，全部弃权 | ≥95% |
| 一级分类，依赖预测类型 | 0/160，全部弃权 | 0/160，全部弃权 | ≥90% |
| BGE 一级分类，额外提供正确类型 | 111/160（69.38%） | 115/160（71.88%） | 仅诊断，不替代端到端指标 |

模型对交易状态提示也全部弃权，所以全部 200 条都需要人工补充。40 条需澄清样例没有被错误判为明确单笔，但 160 条明确单笔也没有被接受，**这不能算防误记能力已验证**。

开发集比较了三种金额提示、两种类型提示及 0.3 / 0.5 / 0.7 阈值。金额最佳为“金额”配 0.3，命中 66/80；类型提示全部为零命中，按预设同分规则选择 0.7。提示与上下文在测试前冻结，没有根据测试失败继续调优。之后仅补充许可证、门槛边界检查、格式整理并复核结果，不把重复检查算成新的独立测试。

最小规则基线的金额、类型、分类分别为 89/160、141/160、5/160，40 条需澄清样例中误接纳 20 条。该基线只是诊断参照，不是拟上线方案，也没有用于填补模型输出。

## 失败与定位

| 原句 | 正确结果 | 本轮结果 | 问题 |
|---|---|---|---|
| 我的车充电花了30块 | 3000 分，支出，交通 | 金额正确，类型弃权；给定类型后分类为居住 | 类型领域迁移、充电语义区分不足 |
| 昨晚电车充电付了四十二元五角 | 4250 分 | span 仅“四十二元”，输出 4200 分 | 模型截断角分后缀 |
| 给妹妹生日红包六十六元六角六分 | 6666 分 | span 仅“六十六元”，输出 6600 分 | 模型截断角分后缀 |
| 猫砂两袋总共49块9 | 4990 分 | span 仅“49块”，输出 4900 分 | 口语金额尾数截断 |
| 到账工资8000元（控制样例） | 收入 | 类型标签概率极低，弃权 | 当前零样本 schema 不能胜任记账类型分类 |

INT8 的 17 条金额失败中，6 条没有完整可用金额，11 条得到了错误金额；主要可见问题是中文角分和口语尾数被截断。完整失败行见 [failures.tsv](failures.tsv)，包括原文、期望字段、预测字段、金额依据和待补项。

整数转换器能正确处理上述完整金额原文；它无法恢复模型未返回的后缀。本轮未通过测试集反向添加补丁后重新声称达标。后续应增加金额边界检查：对紧邻金额片段的角分/尾数先保守弃权，或在新的开发集上验证安全的范围扩展。

转换问题已做有限范围排查：使用官方原始 Paddle 权重的独立 NumPy 前向、转换后的 Torch 与 ONNX FP32，在 7 条控制样例上 span 一致。最大概率绝对误差小于 0.000002；情感分类正向控制能输出“正向”，而金融类型提示仍弃权。这支持“当前模型/提示的领域能力不足”这一判断，不能证明所有提示或微调方案都无效。

## 资源、量化和性能

- UIE INT8：23,529,905 字节；BGE INT8：23,996,863 字节。
- 加上分词文件、模型卡和许可证：48,824,863 字节（48.82 MB），低于 150 MB 资源预算。模型目前在开发机 artifacts 中，**尚未随 APK 打包**；此数字不含移动运行时二进制。
- FP32 与 INT8 在 200 条上的金额输出有 5 条不同；虽然总命中数相同，也不能说量化输出完全一致。
- 5 条 BGE 向量控制样例的 FP32/INT8 余弦相似度约 0.9933–0.9948。它是数值诊断，不是分类正确率。
- Windows / AMD Ryzen 7 9800X3D、CPU 4 线程，200 条顺序解析观测：INT8 p50 约 5.29 ms、p95 约 13.20 ms；单次模型加载及分类缓存构建约 200.94 ms。解析含 5 次 UIE、1 次 BGE、排序和金额转换。系统负载会影响这些值。
- 上述是**桌面观测**，不是红米数据，不是冷启动 p95。ADB 未枚举到设备，手机热/冷解析、PSS、Perfetto、进程重建、首次安装断网识别均未验证。
- Python 侧通过阻断 socket 连接验证本地加载与 UIE/BGE 推理；未验证 React Native 推理或 JS 分词位置一致性。

NumPy 参考实现按官方 UIE 方程独立计算，没有执行完整 PaddleNLP Taskflow。参考对齐只覆盖所列控制样例。原始权重、转换 ONNX、模型 revision 和来源校验值分别见工具的 `sources.json` 与 [export-manifest.json](export-manifest.json)。

## 后续决策

建议先补充**独立的记账训练数据**，验证 UIE 的金额边界、收支类型、交易状态与账户角色微调；分类侧用真实类别定义和代表例句验证 BGE，必要时比较领域微调。当前测试集已用于诊断，后续迭代需准备新的未见验收集。

另一条可行路线是更换具有中文记账/意图分类能力的本地小模型，仍使用相同的资源与设备门槛。不能从本轮结果推导“所有小模型都不行”，也没有理由改用线上推理或纯规则替代。

本轮止于用户计划中“未达到门槛时交付失败样例与数据，重新评估模型或微调需求”的分支。语料人工核验、领域模型选择和目标设备验证完成前，不启用产品识别入口。
