# 账户级联删除设计

## 目标

允许用户在账户编辑页永久删除已有账户，并同时删除所有直接关联数据。删除操作必须明确告知不可恢复，并保证数据库变更具备原子性。

## 交互设计

- 仅编辑已有账户时显示“删除账户”按钮；新建账户时不显示。
- 删除按钮位于保存按钮下方，使用危险操作语义色。
- 点击按钮后只显示一层确认弹窗。
- 弹窗标题包含账户名称。
- 弹窗正文明确说明：
  - 将删除当前账户；
  - 将删除全部关联交易、周期规则和导入映射；
  - 删除永久生效且不可恢复。
- 弹窗提供“取消”和红色“永久删除”两个操作。
- 用户点击“永久删除”后立即执行，不再显示第二层弹窗。

## 级联范围

删除账户时，在同一个数据库事务内按以下顺序处理：

1. 删除 `account_id` 或 `to_account_id` 等于目标账户 ID 的交易。
2. 删除 `account_id` 或 `to_account_id` 等于目标账户 ID 的周期规则。
3. 删除 `kind = 'account'` 且 `target_id` 等于目标账户 ID 的导入映射。
4. 删除目标账户。

分类、项目、预算、导入批次和设置不属于账户的直接所有数据，不随账户删除。

## 一致性与错误处理

- 四步删除必须位于单一事务中。
- 任一步失败时回滚全部修改，不允许出现账户已删除但关联数据残留，或关联数据已删除但账户仍存在的中间状态。
- 删除进行时禁用保存与删除按钮，防止重复提交。
- 删除失败时停留在编辑页，并显示错误信息。
- 删除成功后关闭编辑页。

## 缓存失效

删除成功后刷新：

- 账户余额与账户列表；
- 交易列表、详情与汇总；
- 统计、预算和分类推荐基线；
- 周期规则与待处理周期任务。

导入映射没有独立界面缓存，无需额外刷新。

## 代码边界

- Repository 提供单一的账户级联删除函数，封装事务和依赖删除顺序。
- Hook 负责调用 repository，并集中失效账户、交易和周期规则查询。
- 账户编辑页只负责危险按钮、确认弹窗、加载状态、错误展示和成功关闭，不直接操作数据库。
- 现有归档功能保持不变，作为可恢复的替代操作继续存在。

## 测试

### 自动测试

- Repository 测试验证删除顺序覆盖交易、周期规则、账户导入映射和账户。
- 测试同时覆盖账户作为转出账户与转入账户的查询条件。
- 测试验证 repository 使用单一事务执行。
- Hook 或缓存辅助逻辑测试验证周期规则与交易相关查询均被失效。

### 人工检查

- 新建账户页不显示删除按钮。
- 编辑账户页显示删除按钮。
- 点击删除只出现一层弹窗，正文包含级联范围和不可恢复说明。
- 点击取消不修改任何数据。
- 点击“永久删除”后账户、关联交易、周期规则和导入映射均消失。
- 删除后资产、统计和预算立即刷新。
- 模拟删除失败时数据保持完整，编辑页显示错误。

## 风险

- 关联交易删除会改变历史统计、预算执行情况和净资产趋势，这是级联删除的预期结果。
- 删除无法通过应用内操作撤销；用户需要依靠删除前已导出的备份恢复。
- 大量历史交易的删除可能需要短暂等待，界面必须保持 pending 状态并阻止重复点击。
