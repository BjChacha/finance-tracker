# 交互、主题与二级卡片性能优化设计

## 背景

本次优化覆盖四个相互关联的体验问题：页签页面、底部光标与图标高亮不同步；Android 原生记账小键盘未完整跟随应用主题；交易详情和资产详情二级卡片入场首帧不完整且伴随明显卡顿；“记一笔”中的日期时间仍呈现为普通输入框。

项目基于 Expo SDK 57、Expo Router、自定义页签分页器、Reanimated 4 和本地 Expo Android 模块。设计以保留现有导航与数据模型为前提，不迁移路由架构、不新增主题持久化格式、不改变交易日期存储格式。

## 设计目标

- 页签页面、底部高亮光标、图标与文字高亮由同一个连续进度驱动。
- 点击、滑动、快速反向接管与 Reduced Motion 下的三层视觉状态始终一致。
- 原生记账小键盘支持应用内全部主题，并在桌面快捷方式冷启动时使用最近一次应用主题。
- 二级卡片从屏幕底部之外、完全不可见的状态开始连续入场，不出现第一帧局部露出。
- 卡片移动阶段不挂载重型编辑器，避免 Fabric mount、布局和绘制阻塞入场动画。
- 交易详情通过显式预取降低首次内容等待，但动画正确性不依赖预取是否完成。
- 日期时间栏采用已经确认的紧凑语义双卡，降低整体高度并保留原生选择器。
- 改动保持局部、可测试、可回滚，不引入新的跨模块全局状态。

## 非目标

- 不迁移到 Expo Router 原生 Tabs。
- 不把二级卡片迁移为原生 `formSheet`。
- 不重写交易表单、资产编辑器或现有页签状态机。
- 不修改数据库 schema、交易日期格式或主题设置键。
- 不以延长动画时间掩盖主线程卡顿。

## 方案选择

采用渐进式重构：保留自定义页签和透明 Modal，由统一共享值驱动页签视觉；为原生小键盘增加显式主题载荷；将二级卡片拆分为轻量动画外壳和延迟挂载内容；保留现有日期时间选择器，仅重做触发控件。

未采用原生 Tabs 与 `formSheet` 迁移，因为该方案会扩大导航改动范围，并引入 Android/iOS 在高度、圆角、手势和背景处理上的差异。未采用单纯预加载方案，因为 SmartPerfetto 表明第二次打开仍存在重型 mount 和 draw，预加载不能消除动画阶段的主线程竞争。

## 页签同步动画

### 当前问题

页面位移和底部光标已经使用 UI 线程共享值，但图标与文字颜色依赖切换完成后的 React `activeName`。因此页面和光标正在移动时，图标仍保持旧状态，直到路由落定后才跳色。

### 连续视觉进度

页签分页器向底部页签栏提供只读连续位置 `visualTabPosition`。该值以页签索引为坐标：整数表示落在某个页签，小数表示位于相邻页签之间。

以下视觉属性只从该值派生：

- 页面容器位移。
- 高亮光标水平位置。
- 每个页签的高亮图标和文字透明度。
- 选中页签的轻微缩放。

每个页签项的高亮权重为 `1 - clamp(abs(visualTabPosition - tabIndex), 0, 1)`。非相邻页签的高亮权重恒为零。

### 双层图标与文字

每个页签项叠放两层完全相同的图标与文字：底层使用未选中颜色，顶层使用选中颜色。顶层透明度使用连续高亮权重，缩放在 `0.96` 与 `1` 之间插值。

该方案不向 SVG 组件逐帧传递动态颜色，避免不同图标实现和平台动态颜色对象在 Worklet 中表现不一致。两层只参与透明度和 transform 动画，不触发布局。

### 状态与无障碍

`activeName` 继续表示已经落定的路由页，负责 `accessibilityState.selected`、焦点语义和 Router 一致性。它不再控制逐帧颜色。

程序切换、手势跟手、快速接管和返回动画均复用现有视觉进度。Reduced Motion 下保留手势跟手，释放或点击时页面、光标和图标一起原子落位。

### 影响范围

- `src/components/navigation/tab-pager.tsx`
- `src/components/navigation/tab-bar.tsx`
- `src/components/navigation/tab-pager-machine.ts`
- 现有页签 machine、controller 与 tab bar 测试

## 原生记账小键盘主题同步

### 当前问题

React 页面内的小键盘已经读取应用主题。独立 Android `QuickKeypadActivity` 使用 AppCompat Day/Night 资源，只能跟随系统明暗，无法正确表达应用内固定的 Light、Dark、Tiffany、Mint 与 Auto 解析结果。桌面快捷方式启动 Activity 时也没有 React 上下文可供即时读取。

### 主题数据边界

应用的 resolved theme 是唯一主题来源。React 侧将原生小键盘需要的最小语义色生成一个类型化载荷：

- `isDark`
- `background`
- `surface`
- `text`
- `secondaryText`
- `border`
- `primary`
- `onPrimary`

载荷只描述语义颜色，不传递完整 Theme 对象，避免本地模块与 React 主题实现过度耦合。

### 同步流程

Theme Provider 完成主题解析后调用原生模块同步一次；主题设置变化后再次同步；从应用内打开小键盘前携带当前载荷再次覆盖，防止原生缓存过期。

原生模块把载荷保存到专用 SharedPreferences。`QuickKeypadActivity` 在构造视图前读取持久化主题，并显式应用窗口背景、面板、文字、边框、按钮和强调色。桌面快捷方式冷启动复用同一份持久化主题；首次安装且主应用从未同步过时才回退到系统 Day/Night。

### 生命周期与失败回退

- 无效或不完整载荷不覆盖上一份有效主题。
- 应用内启动时以本次传入载荷为最高优先级。
- SharedPreferences 不可用或载荷损坏时回退到资源主题，Activity 仍可打开。
- 主题同步失败不阻断 React 主界面，也不修改应用主题设置。

### 影响范围

- `src/theme/ThemeContext.tsx`
- `src/theme/themes.ts`
- `src/lib/quickKeypad.ts`
- `modules/quick-keypad/src/QuickKeypadModule.ts`
- `modules/quick-keypad/android` 下的模块、Activity 与主题辅助代码

## 二级卡片完整入场与性能隔离

### 基线结论

在 USB 连接的 Android 15、120Hz 真机上使用 SmartPerfetto 采集到以下基线：

- 交易详情首次打开的最大应用帧约为 81.9ms，再次打开仍约为 67.2ms。
- 资产详情首次打开约为 40.8ms，再次打开约为 36.5ms。
- 主要耗时集中在 Fabric pre-mount、mount、布局遍历和绘制，并与卡片入场阶段重叠。

首次查询和模块加载会放大交易详情冷启动，但第二次打开仍卡顿，说明核心问题不是单一数据冷启动，而是重型内容挂载与动画争用主线程。

### 外壳与内容分离

`SecondarySheetScreen` 负责唯一的卡片几何和遮罩动画。业务路由只提供内容，并根据外壳状态决定何时挂载重型编辑器。

入场状态依次为：

1. `hidden`：路由已挂载，卡片外壳不可见且不可交互。
2. `measuring`：获取卡片目标高度和安全区信息。
3. `entering`：轻量外壳在 UI 线程从屏幕底部之外移动到目标位置。
4. `settled`：外壳完全稳定，允许挂载重型业务内容。
5. `contentReady`：真实内容替换占位状态并短暂淡入。

卡片初始偏移使用实际测量高度加底部安全余量，不能依赖固定百分比。测量完成前保持 `opacity: 0`，确保任何设备高度和内容尺寸下都不会出现局部卡片首帧。

### 动画行为

- 入场时长约 260ms，使用前快后缓的 timing easing。
- 卡片只动画 `translateY` 与 `opacity`，不动画高度、top、padding 等布局属性。
- 遮罩独立淡入，不参与卡片测量。
- 外壳开始移动后才启用卡片区域触摸；进入 `settled` 后才启用业务表单触摸。
- 退出期间保留已经挂载的业务内容，先完成整卡下移动画，再卸载路由。
- Reduced Motion 下外壳直接落位，然后挂载内容；不显示中间局部状态。

### 真实摘要与渐进式编辑器

首轮实现使用固定结构占位内容隔离卡片动画。真机复测确认卡片入场窗口已经稳定，但完整编辑器在 `onEntered` 后一次性挂载，仍产生交易详情约 142ms、账户详情约 85ms 的重帧。交易重帧包含约 279 条 Fabric 插入指令和 285 条布局更新，证明占位方案移动了重负载时机，但没有降低编辑器首挂载成本。

最终方案不再显示通用占位符。交易详情和账户详情在 `entering` 阶段立即挂载对应业务组件的轻量 summary 模式，显示缓存中的真实金额、类型、分类、账户、日期或账户名称等核心信息。summary 模式同时初始化表单状态和数据订阅，但不创建完整编辑控件树。

外壳触发 `onEntered` 后，同一个组件实例切换到 editor 模式，按帧分批增加原生视图：

1. 首批挂载金额、类型和首屏核心字段。
2. 后续帧挂载分类、账户和日期等选择控件。
3. 最后挂载备注、项目、图标、颜色和非可见弹层入口。

分批过程不重置表单状态，不引入第二个业务数据源，也不动画高度。位于首屏下方的内容允许延后一个或数个帧出现；用户已经在 summary 模式看到真实信息，因此不出现虚假加载状态。

查询失败、记录不存在或编辑器初始化失败不影响外壳入场。错误状态在卡片中直接显示，关闭操作始终可用。

### 交易详情预取

抽取可复用的 `transactionQueryOptions(id)`，让详情 Hook 和列表预取使用完全相同的 query key、query function 与缓存策略。

交易行在 `onPressIn` 时先把列表中已有的完整交易快照同步写入详情 query cache，再触发数据库数据校准和详情模块预热；`onPress` 立即导航，不等待预取结果。summary 模式挂载后立即订阅账户、分类、项目和汇率等编辑器依赖，使这些查询与卡片动画并行完成，但预热失败不影响正常导航。

预取只优化内容就绪时间。即使缓存完全未命中，轻量外壳也必须立即、完整地开始动画。

### 并发与取消

- 每次入场生成 session id，旧 session 的完成回调不能挂载新路由的内容。
- 入场中关闭时取消当前进入动画，直接从当前视觉位置执行退出。
- 退出开始后忽略迟到的查询成功和内容挂载请求。
- 快速切换不同详情时，各路由只消费与自身 id 匹配的缓存结果。

### 影响范围

- `src/components/navigation/secondary-sheet-screen.tsx`
- `app/transaction/[id].tsx`
- `app/accounts/edit.tsx`
- 交易列表行的导航入口
- `src/features/transactions/hooks.ts`
- 交易查询 option factory 与相关测试

## 紧凑语义双卡日期时间栏

### 已确认视觉

日期时间区域改为单行双卡。日期卡占较大宽度，时间卡占较小宽度，两张卡高度约 50dp，间距约 8dp。

日期卡只显示日历图标与本地化日期值；时间卡只显示时钟图标与时间值。不显示“日期”“时间”“今天”“现在”等视觉辅助文案，也不保留上一天、今天、下一天和现在等快捷按钮。

### 交互与语义

- 点击日期卡继续打开现有平台日期选择器。
- 点击时间卡继续打开现有平台时间选择器。
- 内部继续维护现有 `dateText` 与 `timeText`，提交格式和校验逻辑不变。
- 小屏设备优先压缩卡片水平 padding 与图标间距，时间卡保持最小可读宽度。
- 视觉不显示字段名，但无障碍标签完整包含类型和值。
- 按钮保持至少 48dp 触摸高度和明确的按压反馈。

### 影响范围

- `src/features/transactions/components/TransactionForm.tsx`
- 日期格式化、表单交互和无障碍测试

## 共享动效约束

- 所有逐帧动画保持在 UI 线程。
- 优先动画 transform 和 opacity，禁止为本次效果动画布局属性。
- 页签高亮使用现有页签转场时序，不建立第二套计时器。
- 二级卡片进入时长保持在 300ms 内，内容淡入不延迟卡片开始移动。
- 所有新动效尊重 Reduced Motion。
- 动效 token 只包含项目内确实复用的 duration 与 easing，不引入通用动画框架。

## 测试设计

### 页签

1. 页面进度为整数时只有对应页签完全高亮。
2. 页面位于两个页签之间时，两者按距离交叉高亮。
3. 点击、手势、动画中反向接管使用相同视觉进度。
4. 路由落定前无障碍选中状态仍保持语义正确。
5. Reduced Motion 下页面、光标和图标原子同步。

### 小键盘主题

1. Light、Dark、Tiffany、Mint 和 Auto resolved theme 生成正确原生载荷。
2. 主题变化覆盖 SharedPreferences 中的旧值。
3. 应用内启动使用本次载荷。
4. 桌面快捷方式冷启动使用最近一次应用主题。
5. 首次启动和损坏载荷安全回退到资源主题。

### 二级卡片

1. 测量完成前卡片保持完全不可见。
2. `onEntered` 之前只渲染真实 summary，不创建完整编辑控件树。
3. 入场中关闭不会迟到挂载内容。
4. 缓存命中时 summary 首帧显示真实数据；查询失败时外壳仍完整进入并显示可关闭错误状态。
5. 退出完成前内容不提前卸载。
6. 快速打开不同记录时旧 session 不覆盖新内容。

### 日期时间

1. 双卡分别打开日期与时间选择器。
2. 显示值与提交值转换保持现有行为。
3. 不同日期格式和窄屏宽度下不溢出。
4. 无障碍标签包含字段类型和当前值。

## 验证方案

- 运行页签 machine、controller 和 tab bar 专项 Jest。
- 运行主题映射、本地模块接口和交易查询专项测试。
- 运行交易表单与二级卡片组件测试。
- 运行完整 Jest、TypeScript typecheck 和 Expo SDK 57 依赖一致性检查。
- 构建 Android Release APK 并安装到同一 USB 真机。
- 分别采集交易详情与资产详情冷启动、第二次打开各至少三次 SmartPerfetto trace，并覆盖点击后 700ms 的完整交互窗口。
- 人工验证五种应用主题、桌面快捷方式冷启动、快速页签接管、快速开关详情和窄屏日期栏。

性能验收标准：

- 点击详情到卡片开始移动不超过 100ms。
- 卡片入场期间应用帧 P95 不超过 16.7ms。
- 卡片入场期间不存在超过 33ms 的应用帧。
- 点击后 700ms 内不存在由编辑器批量 Fabric mount 引起的超过 33ms 应用帧。
- summary 到 editor 的切换不得清空、闪烁或重置真实业务数据。
- 120Hz 设备的进阶目标为应用帧 P95 接近 8.33ms。
- 首帧不得显示任何局部卡片。
- 冷启动与第二次打开都必须满足完整入场语义。

## 风险与控制

- 双层页签图标会增加少量视图数量，但只覆盖固定页签项，且避免逐帧 React render。
- 原生主题载荷与应用主题字段可能演进不同步，通过独立 mapper 和穷尽测试控制。
- 渐进式挂载可能让屏幕下方编辑区延后数帧出现；summary 提供真实数据连续性，分批边界保持在独立表单区块之间。
- 卡片实际高度可能在内容挂载后变化；外壳目标几何必须独立于重型内容，真实内容在稳定容器内滚动或布局。
- SmartPerfetto 的 SurfaceFlinger 聚合数据可能受设备系统界面干扰，验收以应用进程时间窗和主线程、RenderThread slice 为准。
