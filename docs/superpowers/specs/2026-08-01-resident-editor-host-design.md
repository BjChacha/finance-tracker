# 交易与资产详情双常驻编辑器设计

## 背景

当前交易详情和资产详情通过透明 Modal 路由渲染 `SecondarySheetScreen`，并在卡片入场后把轻量摘要切换为完整编辑器。分帧挂载已经消除了百毫秒级重帧，但摘要与完整编辑器使用不同排版，切换时仍能明显感知元素位置和结构变化。

现有代码已经复用 `TransactionForm` 与 `AccountEditor` 的组件定义，真正重复发生的是每次打开路由时创建新的 React 实例、Fabric 原生视图、布局和绘制。仅预加载 JavaScript 模块或查询数据不能消除这部分成本。

## 目标

- 交易详情始终复用一个已挂载的 `TransactionForm` 实例。
- 资产详情始终复用一个已挂载的 `AccountEditor` 实例。
- 首张可见帧直接显示最终编辑器排版，不再出现独立摘要与完整编辑器之间的视觉切换。
- 在应用首屏稳定后后台预热两套编辑器，避免影响启动首帧。
- 保留交易与资产详情现有路由、深链、Android 返回键和导航历史语义。
- 保证不同记录之间的数据、自动保存、弹层与异步回调严格隔离。
- 将常驻实例数量和额外内存控制在固定上限。

## 非目标

- 不为每条交易或资产保留独立编辑器实例。
- 不把新增交易、快捷记账或新增资产流程迁入常驻 Host。
- 不迁移到原生 `formSheet`，不重写整个 Router Stack。
- 不预挂载日期选择器、系统弹窗等仅在交互时出现的临时原生界面。
- 不修改数据库 schema、交易数据模型或资产数据模型。
- 不以恢复摘要模式作为低内存降级方案。

## 方案决策

采用双常驻 Host：根布局持有一个交易编辑器实例和一个资产编辑器实例。两个实例在应用进程生命周期内最多各挂载一次，未激活时隐藏视觉、触摸和无障碍，但保留原生视图。

未采用单常驻插槽，因为在交易详情与资产详情之间切换仍会重挂载另一类编辑器。未采用按记录建立实例池，因为其内存、脏状态和自动保存复杂度会随访问记录数量增长。

## 根级架构

`AppShell` 在 Router Stack 上方渲染唯一的 `ResidentEditorSheetHost`。Host 包含共享卡片外壳、遮罩、动态标题和操作按钮，以及两个重叠的常驻编辑器图层。

`transaction/[id]` 与 `accounts/edit` 保留为透明 Modal 路由，但改为轻量控制器。路由挂载时向 `EditorSheetCoordinator` 提交目标类型和记录 ID，路由本身不再创建 `SecondarySheetScreen` 或编辑器。Host 完成退场动画后调用 `router.back()`，从而保留现有导航历史和深链入口。

现有 `SecondarySheetScreen` 拆分为两层：

- 无 Router 依赖的 `SecondarySheetSurface`，只负责遮罩、卡片几何、入退场动画、标题区域和交互屏障。
- 保留原 API 的 `SecondarySheetScreen` 包装器，继续服务其他二级页面。

`ResidentEditorSheetHost` 直接复用 `SecondarySheetSurface`，避免常驻 Host 与普通二级卡片维护两套动画实现。

## 组件边界

### ResidentEditorSheetHost

- 持有共享卡片外壳和两个常驻编辑器图层。
- 根据 Coordinator 状态决定当前激活类型、标题、操作按钮和返回行为。
- 未激活图层保持挂载，但设置为不可见、不可触摸且不参与无障碍导航。
- 卡片关闭时 Host 仍存在，只把外壳移动到屏幕之外并隐藏遮罩。

### EditorSheetCoordinator

- 管理唯一活动会话和单调递增的 `sessionToken`。
- 接收路由提交的打开、关闭和返回请求。
- 协调数据准备、编辑器 hydration、首屏就绪屏障和卡片动画。
- 丢弃所有不匹配当前 token 的迟到查询、动画和保存回调。

### ResidentTransactionEditor

- 在后台预热时创建唯一 `TransactionForm` 实例。
- 只服务交易详情编辑，不服务新增或快捷记账。
- 接收显式交易会话，不再依赖挂载时的一次性 `initialValues`。

### ResidentAccountEditor

- 在后台预热时创建唯一 `AccountEditor` 实例。
- 只服务资产详情编辑，不服务新增资产。
- 接收显式资产会话并原子重置字段与临时 UI 状态。

## 会话状态机

每次打开详情生成新的 `sessionToken`，状态依次为：

1. `idle`：编辑器已挂载但隐藏，不允许输入和自动保存。
2. `preparing`：解析记录 ID，读取同步缓存并启动后台数据校准。
3. `hydrated`：通过单次 reducer action 写入全部字段，并重置滚动、键盘、弹层和临时选择。
4. `opening`：首屏布局确认后启动卡片入场。
5. `active`：开放输入、删除和自动保存。
6. `closing`：停止接收新输入，处理当前会话保存并执行退场。
7. `idle`：卡片完全离屏，路由返回，常驻实例继续保留。

状态机任何阶段都只接受与当前 `sessionToken` 匹配的异步结果。新会话不能观察到上一条记录的数据或临时交互状态。

## 编辑器状态重构

当前 `TransactionForm` 通过多个 `useState(initialValues)` 初始化字段，无法安全地在同一实例中切换记录。交易编辑器需要把业务字段和临时 UI 状态收敛到会话 reducer，提供原子 hydration 动作。

交易 hydration 至少覆盖类型、金额、手续费、账户、目标账户、分类、项目、日期、时间、备注、币种和汇率，同时关闭键盘、日期时间选择器、分类弹层和币种弹层，并复位滚动位置和交互标志。

资产编辑器采用相同原则，原子写入名称、类型、图标、颜色、初始余额、当前余额语义和计入总资产开关，并关闭余额调整、小键盘、确认弹窗及临时输入状态。

编辑器对外暴露会话输入和就绪信号，不暴露内部零散 setter。新增流程继续使用现有独立实例和 API，避免常驻生命周期影响创建流程。

## 数据准备与缓存

从交易列表打开时，继续在 `onPressIn` 把完整 `TxListItem` 同步写入详情 query cache，并后台查询数据库校准。资产列表已有完整的 `AccountWithBalance` 集合，Coordinator 从账户缓存同步提取目标快照。

冷深链没有同步快照时，Host 保持不可见，先查询目标记录。查询成功后再 hydration 和入场；查询失败或记录不存在时，使用同一共享卡片外壳显示可关闭错误状态，绝不显示上一会话数据。

编辑器预热期间订阅账户、分类、项目、币种和汇率等共享数据。隐藏编辑器可以响应主题与共享数据变化，但 `idle` 状态禁止自动保存和业务 mutation。

## 后台预热

应用主页面首帧、页签状态和首次交互屏障稳定后，启动 `ResidentEditorPrewarmer`。预热优先顺序为交易编辑器、资产编辑器，因为交易详情使用频率和原生视图数量更高。

预热按小批次挂载原生控件，每批主动让出执行权。检测到用户导航、手势或新的详情打开请求时，普通后台预热暂停；若打开目标编辑器尚未就绪，则提升该类型为前台优先级，只完成首屏就绪所需控件，屏外控件随后继续。

预热失败不阻断应用启动，并在下一次空闲窗口重试。用户点击尚未成功预热的编辑器时，Coordinator 执行前台准备，但仍不回退到摘要界面。

## 视觉与交互

- 不再使用 `summary` 视觉模式或摘要到编辑器的内容替换。
- 目标记录必须完成原子 hydration、滚动复位、键盘与弹层关闭、首屏布局确认后，卡片才能从不可见状态开始入场。
- 第一张可见帧已经包含最终标题、操作按钮、金额、分类、账户、日期或资产字段排版。
- 入退场期间只动画共享外壳的 `translateY` 与 `opacity`，不动画内部布局属性，不对编辑器内容做淡入或交叉切换。
- 入场完成后统一开放表单触摸和自动保存。
- 关闭时先禁用输入并处理保存，再保留完整内容执行整卡退场；离屏后才切换会话状态和路由。
- 每次打开默认滚动到顶部，不继承上一条记录的滚动位置。
- Reduced Motion 下跳过位移动画，但仍保留数据与布局就绪屏障。

用户在首屏出现后立即点击且预热尚未完成时，可以增加少量点击到动画开始的准备时间，但不显示摘要、空白字段或半成品首屏。目标准备时间不超过 100ms。

## 自动保存与关闭

自动保存只在 `active` 状态运行，并使用记录 ID 与 `sessionToken` 组成会话键。关闭请求进入 `closing` 后不再接受新编辑，先执行现有的 dismiss gate 和待保存处理。

保存失败时保持卡片打开并保留用户输入，不进入退场或下一会话。保存已经提交但回调迟到时，数据库结果可以完成，但回调只有在 token 仍匹配时才能修改当前 UI。

删除成功后标记当前会话不再需要自动保存，执行退场并返回上一层。删除失败时恢复当前会话的保存能力并显示错误。

## 资源与内存边界

- 常驻上限固定为一个交易编辑器和一个资产编辑器。
- 日期选择器、系统 Alert、删除确认和只在打开时存在的 Modal 不常驻。
- 隐藏编辑器禁止触摸、输入、动画和自动保存，但保留原生视图与共享查询订阅。
- 应用进入后台后保持两个实例；操作系统回收进程时接受自然销毁，重新启动后再次预热。
- 双编辑器相对未预热基线的额外 PSS 内存目标不超过 30MB。
- 如果超过预算，优先减少屏外非常用控件的常驻范围，不恢复独立摘要模式，也不增加按记录缓存。

## 并发与异常

- 快速打开不同记录时，只有最后一个路由会话可以进入 `opening`。
- 入场中返回时从当前视觉进度执行退场，未完成的前台准备结果失效。
- 退场开始后忽略新的表单交互和迟到的数据校准结果。
- 主题或共享数据在隐藏期间变化时，编辑器可以更新，但不得激活自动保存。
- 预热失败、记录查询失败、记录被删除和保存失败均保留可用的关闭路径。
- 路由异常卸载时 Coordinator 强制使对应 token 失效并隐藏 Host，避免悬空遮罩。

## 测试设计

### 单元测试

- 会话状态机只允许合法状态转换。
- hydration 使用一次 reducer action 完整替换记录状态。
- 旧 `sessionToken` 的查询、动画和保存回调被忽略。
- 会话切换复位滚动、键盘、弹层和临时选择状态。
- 自动保存只在 `active` 状态运行，并绑定正确记录。

### 组件与集成测试

- 应用首屏稳定前不启动编辑器预热。
- 预热顺序为交易编辑器后资产编辑器，并能在用户交互时暂停。
- 连续打开多个交易时 `TransactionForm` 只挂载一次。
- 连续打开多个资产时 `AccountEditor` 只挂载一次。
- 两类详情互相切换时两个常驻实例都不重挂载。
- 第一张可见帧与稳定后的首屏元素树及布局一致。
- 新记录可见前不存在上一条记录数据。
- 深链冷启动、记录不存在、保存失败、删除失败和快速返回均保持正确路由与关闭行为。
- 隐藏编辑器不响应触摸、不进入无障碍焦点、不触发自动保存。

### 真机性能与视觉验证

- 使用 Android Release APK 和同一台 Android 15、120Hz 真机采集 SmartPerfetto。
- 分别采集应用启动、后台预热、首页滑动、交易详情首次打开、资产详情首次打开和连续记录切换。
- 点击详情后的应用进程 trace 中不得出现编辑器批量 Fabric `createView` 或大批量 mount。
- 卡片入场期间不得出现超过 33ms 的应用帧，P95 目标不超过 16.7ms，120Hz 进阶目标接近 8.33ms。
- 后台预热不能在首页滑动或页签切换期间制造超过 33ms 的应用帧。
- 点击到卡片开始移动目标不超过 100ms。
- 比较预热前后 PSS，双常驻编辑器额外内存不超过 30MB。
- 至少执行三轮首次打开与连续切换，并人工确认无摘要切换、无旧数据闪现、无首屏元素跳位。

## 实施顺序

1. 抽取无 Router 依赖的共享卡片动画 Surface，并保持现有二级页面行为不变。
2. 建立 Coordinator、会话状态机和根级 Host，但暂不接管现有详情路由。
3. 将交易编辑器改为可原子切换的常驻会话模型，接入交易详情路由并验证自动保存。
4. 将资产编辑器改为相同会话模型，接入资产详情路由。
5. 增加首屏稳定后的双编辑器后台预热和用户交互抢占。
6. 删除详情路径中的摘要视觉模式与渐进替换逻辑，保留其他创建流程的独立实例。
7. 完成单元、集成、Release 构建、内存测量和 SmartPerfetto 前后对比。
